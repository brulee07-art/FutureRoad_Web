# 퓨처로드 주행 채점

제2회 퓨처로드 자율주행 자동차 제작 캠프의 9개 팀을 위한 태블릿 채점 및 실시간 전광판 프로그램입니다.

[홈페이지](https://www.futureroad.kr/) · [주행 채점](https://www.futureroad.kr/driving.html) · [실시간 순위](https://www.futureroad.kr/driving-display.html) · [GitHub에서 수정·관리하기](docs/GITHUB.md)

## 사용 방법

1. 운영본부에서 안내받은 ID와 비밀번호로 로그인한 뒤 `실전` 또는 `테스트`를 선택합니다. 두 기록은 별도로 저장됩니다.
2. 팀과 `1차 주행` / `2차 주행`을 선택합니다.
3. 무선 스톱워치로 측정한 실제 주행시간을 분·초로 입력합니다. 소수점 둘째 자리까지 입력할 수 있습니다.
4. 자율주행으로 성공한 항목을 체크합니다. 체크를 해제하면 차감시간도 즉시 복구됩니다.
5. `기록 확정 · 순위 반영`을 누릅니다. 저장 완료 메시지를 확인합니다.
6. 전광판 PC에서 `전광판 열기`를 누릅니다. 결과는 2초마다 자동으로 갱신됩니다.
7. `전체 순위`에서 CSV로 결과를 내려받을 수 있습니다.

입력 중인 값은 해당 브라우저에 임시 보관됩니다. 확정한 값은 서버에 저장되어 다른 기기에서도 볼 수 있습니다. 네트워크 오류가 발생하면 저장 성공으로 표시하지 않으며, 마지막 확인 결과를 유지합니다.

## 평가 기준

|성공 항목|차감|판정|
|---|---:|---|
|차로 유지 완주|10초|4개 바퀴 모두 트랙 밖으로 벗어난 적 없이 한 바퀴 완주|
|일시정지|5초|정지선 이전 지정 구역에서 완전히 정지하고 2초 이상 대기 후 출발|
|앞지르기·복귀|20초|앞차 추월 후 지정 구간이 끝나기 전에 원래 차로 복귀|
|횡단보도 대응|10초|접촉 없이 정지·대기하고 보행자 모형 통과 후 출발|
|무단횡단 대응|15초|노면 표시 없는 구간에서 접촉 없이 정지하고 보행자 모형 통과 후 출발|

- 완주 회차 기록 = 실제 주행시간 − 성공 항목 차감시간. 회차별 최대 차감 60초.
- 미완주 회차 기록 = 같은 기록 구분(실전/테스트)·같은 회차에서 완주한 팀 중 가장 오래 걸린 기록(성공 차감 적용 후) + 1분 30초. 환산값에 성공 차감을 다시 적용하지 않습니다.
- 미완주 환산값도 1차 임시 순위와 1·2차 합산 순위에 반영하고, 시간 아래에 `(미완주)`를 표시합니다. CSV에는 환산 기록과 완주 여부를 별도 열에 기록합니다.
- 완주 기준 기록이 추가·수정·취소되면 기존 미완주 환산값과 순위도 자동 갱신됩니다. 해당 회차에 완주한 팀이 아직 없으면 `기준 대기`로 두며, 완주 기록이 생기면 자동 계산합니다.
- 각 성공은 회차당 한 번만 인정합니다. 완주 시 실패한 성공 항목에는 가산시간이 없습니다. 미완주는 위의 별도 기준으로 환산합니다.
- 최종 합산 기록 = 1차 기록 + 2차 기록. 합산이 낮은 팀부터 순위를 정합니다.
- 합산 동률이면 단축 폭(1차 기록 − 2차 기록)이 큰 팀이 우선입니다. 성공 차감 또는 미완주 환산을 적용한 기록을 사용하며, 2차 기록이 늘면 단축 폭은 음수입니다.
- 트랙 이탈: 4개 바퀴 모두 허용된 트랙 밖으로 벗어난 상태. 허용된 앞지르기 차로는 이탈이 아닙니다.
- 2차 기록이 하나도 입력되지 않았을 때는 성공 차감을 적용한 1차 기록으로 임시 순위를 표시합니다. 9개 팀의 기록이 모두 있고 동률이 없으면 1~9위 순서로 배치됩니다. 1차 동률은 공동순위이며, 1차 미입력·취소 또는 완주 기준 대기 중인 팀은 순위 없이 아래에 표시합니다.
- 2차 입력이 시작되면 기존 합산 순위로 전환합니다. 미완주 환산값을 포함해 두 회차의 기록이 계산된 팀을 합산합니다. 미입력·취소 또는 완주 기준 대기 중인 회차가 있으면 합산과 순위를 표시하지 않습니다. 1차 단독 기록과 두 회차 합산 기록을 섞어 비교하지 않습니다.
- 채점 화면의 실시간 순위·전체 순위·전광판·CSV는 동일한 순서와 기준을 사용하며, 1차 임시 순위임을 명시합니다.
- 합산과 단축 폭이 모두 같으면 공동순위(1, 1, 3)를 표시합니다.
- 별도의 제한시간을 강제하지 않습니다. 입력 범위 0:00.01~99:59.99는 입력 형식 범위입니다.
- 차감 결과가 음수이면 0으로 바꾸지 않고 계산값 그대로 반영합니다.

`public/track-scoring.pdf` 및 `.png`에는 확정한 트랙과 구간별 평가 기준이 있습니다.

## 접근과 운영

심사위원 1명이 행사 태블릿에서 공통 ID와 비밀번호로 로그인해 채점합니다. 서버는 기록 저장·수정·취소·초기화마다 로그인 상태를 확인합니다. 로그인은 최대 12시간 유지되며 로그아웃하면 서버에서도 해당 세션을 폐기합니다. 태블릿 홈 화면에 바로가기를 추가하여 사용할 수 있습니다. 서버 저장과 전광판 갱신에는 인터넷 연결이 필요합니다.

전광판 PC에서는 홈페이지의 `실시간 순위` 탭을 열면 로그인 없이 결과를 확인할 수 있습니다. 공개 홈페이지와 전광판의 접근 범위는 유지됩니다. 기존 서비스 주소로 직접 접속해도 채점하려면 동일한 로그인이 필요합니다.

운영 설정에는 두 가지 초기화 버튼이 있습니다.

- `테스트 기록만 초기화`: 테스트 기록만 삭제하고 실전 기록은 유지합니다.
- `실전·테스트 기록 일괄 초기화`: 확인란에 `전체 초기화`를 입력하고 `전체 기록 삭제`를 누르면 9개 팀의 실전·테스트 1·2차 기록, 저장 이력과 순위가 모두 초기화됩니다. 현재 기기의 임시 입력도 비웁니다. ID·비밀번호 설정과 로그인 상태는 유지합니다.

삭제한 기록은 복구할 수 없으므로 필요한 결과는 먼저 전체 순위에서 CSV로 저장하세요. 기록을 저장 중일 때는 초기화할 수 없습니다. 다른 기기에 남아 있는 미저장 임시 입력은 삭제 대상이 아닙니다. 개별 회차 취소는 해당 채점 화면에서 가능합니다.

저장 시 기록 버전을 확인하여 다른 화면의 수정 결과를 덮어쓰지 않습니다. 충돌 메시지가 나오면 `최신 기록 불러오기`로 확인한 후 다시 입력합니다.

## 개발 및 데이터

Vinext + React + Cloudflare D1. `lib/scoring.ts`가 팀명·성공 항목·계산 규칙을 관리합니다. 저장 API에서 입력값 검증, 다른 사이트에서 보낸 요청 확인, 중복 요청 처리, 버전 충돌 확인을 수행합니다. 저장 이력은 `attempt_history`에 기록합니다.

- `npm ci`: 의존성 설치
- `npm run dev`: 개발 실행
- `node --test tests/scoring.test.mjs tests/server.test.mjs`: 계산·1차 임시 순위·합산 순위·ID/비밀번호 인증·미인증 차단·세션 만료·로그아웃·로그인 시도 제한·중복 저장·버전 충돌·테스트 초기화·일괄 초기화·삭제 오류 시 트랜잭션 복구 검증
- `node --test tests/api.test.mjs`: 로컬 API 테스트. `TEST_BASE_URL`을 로컬 개발 서버로 지정하고, 로컬 전용 `TEST_JUDGE_ID`와 `TEST_JUDGE_PASSWORD`를 지정해야 합니다. 실전 기록은 만들지 않습니다.
- `npx tsc --noEmit`: 타입 검사
- `npm run db:generate`: DB 스키마 변경 시 마이그레이션 생성

`.openai/hosting.json`의 기존 Site ID와 D1 바인딩을 유지해야 저장된 데이터가 이어집니다. 적용된 마이그레이션은 수정하지 않고 새 마이그레이션을 추가합니다. `.wrangler`, `.sites-runtime`, 환경변수와 인증 정보는 소스에 포함하지 않습니다.

## 심사위원 계정 설정

서버 환경변수 `JUDGE_LOGIN_ID`와 `JUDGE_PASSWORD_HASH`를 설정합니다. 비밀번호 원문은 저장하지 않으며, 해시 형식은 `pbkdf2-sha256$100000$32자리 hex salt$64자리 hex hash`입니다. 두 값은 호스팅의 비밀 환경변수로 관리하고 공개 GitHub·프런트엔드·안내문에 비밀번호를 넣지 않습니다. 환경변수를 바꾼 뒤 서비스를 다시 배포합니다.

로그인 토큰은 무작위 256비트이며 서버에는 환경 설정과 결합한 해시만 보관합니다. ID 또는 비밀번호 해시를 바꾸면 기존 토큰은 효력을 잃습니다. 브라우저에서는 탭 단위 세션 저장소를 사용하고, 저장소가 제한된 환경에서는 현재 화면의 메모리로 동작합니다. 로그인은 제3자 쿠키 허용에 의존하지 않습니다. 5분 동안 같은 IP에서 10회를 초과하거나 전체 100회를 초과한 로그인 시도는 제한됩니다.
